# RepoMark Non-Goals (v1)

To maintain cryptographic rigor, developer trust, and clear system boundaries, RepoMark explicitly defines what it is **NOT** designed to do. The following items are out of scope.

---

## 1. No Universal AI-Code Detection
- RepoMark does **not** attempt statistical heuristic detection of whether arbitrary, un-watermarked code was generated by large language models (LLMs).
- RepoMark's watermarking capabilities only track explicitly sealed and marked artifacts with known cryptographic seeds and recipient keys. Un-instrumented third-party AI code cannot and will not be identified via AI-detection heuristics.

## 2. No DRM or Copy-Prevention
- RepoMark provides **provenance, integrity, and forensic attribution**, not Digital Rights Management (DRM).
- RepoMark cannot prevent a recipient from copying, sharing, screenshotting, or executing plain text source code. Any party with read access to the file can replicate the bytes. Protection is forensic and verifiable after the fact, not preventive.

## 3. No Automatic Legal-Ownership Determination
- RepoMark cryptographically proves that a specific public key signed a specific raw byte tree at a given time with an asserted claim kind.
- Cryptographic signatures do not substitute for legal contracts, copyright registrations, or patent rulings. RepoMark establishes admissible technical evidence; it does not adjudicate intellectual property disputes.

## 4. No Invisible Unicode or Homoglyph Tricks
- RepoMark **strictly prohibits** injecting zero-width characters (e.g., `U+200B`, `U+FEFF`), invisible spaces, homoglyphic Cyrillic/Greek substitutions, or malicious bidirectional override tokens (`U+202E`) into source files.
- All watermarking schemes must operate transparently on syntax and AST structures (e.g., formatting permutations, canonical variable renamings, or AST token ordering). Invisible Unicode attacks create severe security vulnerabilities (Trojan Source attacks) and degrade developer ergonomics.

## 5. No Rewriting Canonical Git Commit History
- RepoMark **never mutates, rebases, or rewrites** the canonical development branch or Git commit history to "seal" or watermark code.
- Sealing and watermarking only ever operate on an exported snapshot ("clean export"). The original repository commit tree remains untouched and pristine.

## 6. No Claiming Third-Party, Vendored, or Generated Code as Authored
- RepoMark tooling must not be used to claim sole creation (`original-author`) over third-party dependencies, open-source libraries in `vendor/` or `node_modules/`, or machine-generated boilerplate.
- The default claim kind (`verified-origin`) and strict attribution filters enforce clean boundaries around authored vs. imported code.
